## Repeated close callbacks

The application close callback previously started its complete asynchronous
sequence on every invocation. Another callback could enter while the original
native read or later operation was pending, repeating preference writes,
socket stop, embedded-node close and registry/widget cleanup.

The root now reserves one Future before starting the original operation.
Duplicate and reentrant callbacks return that same Future, including its
original error and stack. The first attempt remains retained after failure;
another callback cannot retry a partially completed shutdown.
The original close body is byte-identical: operation order, awaits, owner
checks, passive phases, fallback timer, widget cleanup and exit remain.

mock window channel. It checks concurrent and reentrant calls, one original
native query, shared native failure and no retry after failure. The native
query fails before preferences, SDK or node operations can begin.
