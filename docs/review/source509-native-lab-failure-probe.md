## Source509 change

The producer can collect three passive reads after an original failed native
wallet tour and before stopping its original nodes. Collection requires the
existing explicit diagnostic opt-in and positive source/build/start/initial
production checks. The original error is recorded first. An attempt marker is
retained before collection; unavailable data never authorizes another attempt.

The original ledger RPC client and its whitelist remain unchanged. A separate
client permits only this fixed sequence, with empty parameters:

1. `stats.networkInfo`: retain reported and listed peer counts only.
2. `stats.syncInfo`: retain the numeric state and current/target heights only.
3. `ledger.getFrontierMomentum`: retain the parsed chain-321 height/timestamp.

The shapes follow the pinned node's
[stats API](https://github.com/zenon-network/go-zenon/blob/2d1b929cc3fa5269cf133757d4a6963821137984/rpc/api/stats.go)
and [sync structure](https://github.com/zenon-network/go-zenon/blob/2d1b929cc3fa5269cf133757d4a6963821137984/protocol/interfaces.go).
Reported and listed counts are computed separately, so equality is not assumed.
The reads are sequential snapshots taken after wallet failure/cleanup; they
cannot reconstruct the exact earlier failure instant or establish its cause.

The client uses only the fixed loopback HTTP transport. Its read window is
eight seconds, each request has a two-second bound, and each of at most three
original wires retains the existing one-second close bound. Responses are
capped at 64 KiB, headers at 4 KiB and each response at 1024 read calls. Ownership is checked
around each read. Late-returned original wires are retained and closed once;
a failed close remains unqualified after later successful closes. No read,
financial operation, profile or node is retried or replaced.

Only strict typed counts, states, heights and closed refusal codes are retained.
Peer identities, IPs, names, raw replies, hashes, paths, inputs and exception
text are omitted. The independent reader binds this data to the failed native
diagnostic context. A separate notice carries its exact parent hash and source,
run, attempt, archive and manifest bindings; every notice retains the original
3800-byte bound and every existing negative fact. Data never changes the
original failure, wallet/seed qualification or admission guards.
