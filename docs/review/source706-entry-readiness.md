single type request. It requires the same exact password-field key and kind,
an enabled field and the harness's original reachability check. Only the two
fixed not-ready/not-present replies can remain pending, within a twelve-second
bound and the original process deadline. Other refusals keep `COMMAND_FAILED`
and the finite first-command notice. An inconsistent successful reply refuses;
a deadline never admits input. No type request is replayed, and cleanup,
capture-state checks and failure receipts are unchanged.

One existing Python case is extended in memory. It checks pending-to-ready
ordering with exactly one type, an inconsistent disabled target, an arbitrary
refusal and a readiness deadline with no type request. The earlier finite
projection and first-failure checks still pass. There are no new registered
cases, native executions, on-disk fixtures or local SDK jobs in this control.
